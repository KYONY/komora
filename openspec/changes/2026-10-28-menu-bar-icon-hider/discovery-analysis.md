# Аналіз проблеми: приховувач іконок рядка меню для macOS 27 (Komora)

## Короткий опис контексту

Pelmet 0.10 на macOS 27 згортає рядок, але іконки ліворуч від ╱ лишаються видимими.
Причину виміряно: розпірки Pelmet стоять ЛІВІШЕ від іконок, а macOS переповнює рядок
зліва, тож у « ідуть розпірки, а не іконки [FACT: E8]. Перетягнути розпірки неможливо:
вони невидимі, поки рядок розгорнуто [FACT: S1 MenuBarManager.swift:415-426].

## Виміряні факти (macOS 27.0.1, 26A434)

1. Дисплеї: горизонтальний 2320×1305 pt, вертикальний 1026×1824 pt, масштаб 2.0, вирізу немає [FACT: S2].
2. Нове ім'я іконки без ключа стає найлівішим; ім'я, створене пізніше, — ще лівіше [FACT: E10, E14].
3. Ключ `NSStatusItem Preferred Position <ім'я>` у ВЛАСНИХ налаштуваннях застосунку задає
   місце іконки при кожній реєстрації — і для нового, і для відомого імені, і після
   `removeStatusItem` + повторного створення в тому самому процесі [FACT: E10, E11].
   Це спростовує коментар Pelmet «an app can neither read nor seed one there» [S1 MenuBarManager.swift:54-55].
4. Порядок монотонний: більший ключ — лівіше. Ключі сторонніх іконок тут лежать між 0 і 1000.
   Ключ 0 або відсутній ключ — найлівіше місце. Ключі 1..100 не проходять правіше за системні іконки.
   Перерозкладка займає 0,06–0,09 с [FACT: E12].
5. Позицію власної іконки застосунок читає без дозволу: `button.window.frame` збігається з AX [FACT: E2 у session, E12].
6. Наскрізно: роздільник T з ключем 250, 5 розпірок з ключами 250.001…250.005 і довжиною 449 pt,
   створених при згортанні і видалених при розгортанні. Після згортання у вікні рядка
   головного дисплея лишились тільки розпірки, T, AppF і системні іконки; на другому — так само.
   Після розгортання все повернулось [FACT: E13].
7. Не діють: `_setLayoutIndex:`, `_setOverflowSpecifierPriority:` (значення не зберігається),
   `_statusItemWithLength:withPriority:` (іконка не з'являється), внутрішнє перетягування
   `_startStatusItemDrag:`/`_dragStatusItemWithOffset:`/`_completeStatusItemDrag` [FACT: E5, E9].
8. Немає нових публічних API для порядку; у 27.0 додано лише `expandedInterfaceDelegate/Session` [FACT: S3].

## Припущення (потребують перевірки)

  збігається з правим краєм «» означає, що її НЕ ВИДНО. Скріншотів немає: Screen Recording не надано.
  Користувач перевіряє очима.
- [ASSUMPTION: needs-verification] Межа довжини однієї іконки. E3/E4: 700 і 900 pt прийнято на
  головному дисплеї, 1100+ — ні. Що вертикальний дисплей (1026 pt) обмежує до 513 pt, НЕ підтверджено.
  Тому беремо обережну одиницю Pelmet: min(ширина/2) − 64 = 449 pt, яка спрацювала в E13.
- [ASSUMPTION: needs-verification] Після ⌘-перетягування користувачем MenuBarAgent тримає
  нове місце у своїй таблиці (так стоїть роздільник Pelmet без ключа). Як це взаємодіє з
  нашим ключем — не перевірено: перетягувати мишею мені заборонено.

## Перелік пропозицій

### 1. Власний застосунок Komora з «посіяними» ключами
- **Проблема:** розпірки мають стояти впритул ліворуч від роздільника, а не ліворуч від усього.
- **Пропозиція:** один видимий роздільник-перемикач `‹`/`›` з ключем K. При згортанні
  створювати N розпірок з ключами K+0.001·i і довжиною одиниці; при розгортанні — видаляти.
  Місце роздільника змінювати з меню («лівіше / правіше на одну іконку»), без перетягування.
  Після згортання перевіряти власні рамки: розпірки впритул до T.
- **Результат:** усі іконки ліворуч від T ховаються на обох дисплеях; дозволів не треба.
